# 🏆 Кинонаграды / Awards Search

Веб-сервис отчётов по кинопремиям: собирает награды и номинации фильмов, персон и церемоний
из **Кинопоиска**, **IMDb** и **TMDB** и превращает их в удобные отчёты с сортировкой,
поиском и экспортом.

**Живой инстанс:** https://awards.zonner.site

Стек: **Next.js 16** (App Router) · **PostgreSQL 16** + Drizzle ORM · Tailwind CSS 4 · Docker Compose.

---

## Возможности

### 🎬 Отчёты по премиям Кинопоиска
- Вставьте ссылку вида `kinopoisk.ru/awards/oscar/2026/` — сервис построит отчёт:
  все категории на одной странице, победители выделены, номинанты рядом.
- Табличный вид с сортировкой по любой колонке и мгновенным поиском.
- Страницы Кинопоиска читаются через **Jina Reader** (`r.jina.ai`) — обходит антибот-защиту;
  fallback на markdown-рендер и Wayback Machine.

### 🔎 Поиск всех наград фильма (по Кинопоиску)
- Вводите название и год фильма — сервис сканирует **~24 премии × 3 года** (год выхода
  и два следующих: церемонии обычно проходят позже) и показывает все найденные упоминания.
- Кнопка-бинокль **«Подобрать»**: ищет фильм на самом Кинопоиске и показывает модалку
  с вариантами (постер, название, год, режиссёр, оригинальное название, рейтинг, жанры) —
  выбор автоматически подставляет название и год в форму. Сортировка: новые фильмы сверху.
- Фильм, выбранный через «Подобрать», ищется **точно — по карточке Кинопоиска** (id фильма),
  а не по названию: одноимённые фильмы и похожие названия не подмешиваются. При ручном
  вводе название сопоставляется целыми словами («Она» не найдёт «Корона»).
- Результаты сканирования кэшируются в PostgreSQL: первое сканирование года занимает минуты,
  повторные — мгновенны. Отсутствующие страницы запоминаются отдельно (TTL 24 ч); если же
  Кинопоиск просто не ответил, страница не помечается отсутствующей, а в результатах
  появляется предупреждение с кнопкой «Досканировать».
- Отчёты текущего года обновляются сами: пока победители не объявлены — раз в 12 часов,
  после объявления — раз в неделю; отчёты прошлых лет считаются окончательными.

### ⭐ IMDb: фильмы, персоны, церемонии
- Поиск фильма → **все** номинации со всех церемоний (рекурсивно через пагинацию
  api.imdbapi.dev), группировка по событиям, фильтр «только победы».
- **Галерея постеров**: клик по постеру увеличивает его; «смотреть всю галерею» открывает
  модалку-сетку (по умолчанию 3×3, размер настраивается от 2×2 до 6×6) с листанием всех
  изображений фильма; полноэкранный просмотр со стрелками (← →).
- **Скачивание галереи одним ZIP**: все изображения в полном размере, архив называется
  `<официальное название> img.zip` (например, `Ready or Not img.zip`). ZIP стримится —
  скачивание начинается сразу, сервер не держит сотни мегабайт в памяти.
- Страница персоны: фильмография + награды; страница церемонии: все номинанты года.

### 🎞 TMDB
- Поиск наград через TMDB (нужен бесплатный API-ключ, вводится в UI или через env).

### 📥 Экспорт
- Любой отчёт (премия / фильм / IMDb) выгружается в **XLSX** (автоширина колонок,
  перенос строк), **Markdown** и **HTML**.

## Быстрый старт

```bash
git clone https://github.com/metalinjector/awards-search.git
cd awards-search
docker compose up -d --build
# → http://localhost:3000
```

Подробная инструкция по развёртыванию, переменным окружения, бэкапам БД и устранению
неполадок — в **[DOCKER.md](DOCKER.md)**.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да (задана в compose) | Подключение к PostgreSQL |
| `POSTGRES_PASSWORD` | нет | Пароль БД (по умолчанию `postgres`) |
| `ADMIN_TOKEN` | нет | Разрешает сохранять/удалять ключ TMDB через интерфейс |
| `TMDB_API_KEY` / `TMDB_ACCESS_TOKEN` | нет | Включает раздел TMDB |
| `JINA_API_KEY` | нет | Повышает лимиты Jina Reader при чтении Кинопоиска |

Переменные задаются в файле `.env` (шаблон — `.env.example`).

### Разработка

```bash
npm ci
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/app_db npm run dev
npm run lint && npm run typecheck && npm test    # то же самое выполняет CI
```

## Архитектура

```
docker compose
├── app  (Node 22 Alpine)          ├── db  (postgres:16-alpine)
│   Next.js 16 standalone, :3000   │   том pgdata
│   при старте: ждёт БД →          │
│   миграции (drizzle/) → сервер   │
```

- **`src/lib/parser.ts`** — загрузка и парсинг страниц премий Кинопоиска (Jina HTML →
  Jina markdown → Wayback fallback).
- **`src/lib/search-service.ts`** — план сканирования «премия × год», кэш отчётов
  и промахов в PostgreSQL.
- **`src/lib/kp-suggest.ts`** — поиск фильмов на Кинопоиске (страница поиска через
  Jina Reader → парсинг markdown).
- **`src/lib/imdb.ts`** — интеграция с api.imdbapi.dev и suggestion-API IMDb:
  титулы, номинации, персоны, церемонии, галерея изображений.
- **`src/lib/film-match.ts`** — сопоставление фильма с номинациями (по id Кинопоиска
  или по названию целыми словами).
- **`src/lib/freshness.ts`** — правила устаревания кэша (когда отчёт ещё может измениться).
- **`src/lib/http.ts`** — общий HTTP-клиент: таймауты и повторы только для 429/5xx/сети.
- **`src/lib/rate-limit.ts`** — лимит запросов с одного адреса на «дорогие» операции.
- **`src/db/schema.ts`** — таблицы: `reports`, `scan_misses`, `imdb_titles`,
  `imdb_events`, `imdb_persons`, `app_settings`; миграции — в `drizzle/`,
  применяются при старте (`src/instrumentation.ts`).
- **`tests/`** — автотесты (vitest) на парсеры, поиск, кэш и ZIP; фикстуры — реальные
  страницы Кинопоиска.
- **`python-prj/`** — исходная десктопная версия (Python GUI), из которой вырос веб-сервис.

Кэш устроен гранулярно по паре **(премия, год)** — уникальные индексы в БД; повторные
запросы уже просканированных лет не обращаются к внешним источникам.

## Доработки после первоначальной версии

Изменения, внесённые при развёртывании и развитии сервиса (июль 2026):

### Исправления развёртывания
1. **`package-lock.json`** — в исходном архиве отсутствовал, из-за чего `npm ci`
   в Dockerfile падал. Сгенерирован и закоммичен.
2. **`drizzle.config.json`** — жёстко указывал `127.0.0.1:5432`, игнорируя `DATABASE_URL`;
   в Docker-сети БД живёт на хосте `db`, поэтому `drizzle-kit push` не мог подключиться
   и контейнер циклически перезапускался. Исправлено на `db:5432`.
3. **`docker-compose.yml`** — приложение подключено к внешней сети `web` для работы
   за reverse-proxy (Caddy) без публикации портов наружу; БД изолирована в приватной сети.

### Ограничение сканирования текущим годом
Для фильма года Y сканировались годы Y, Y+1, Y+2 — включая ещё не наступившие
(для 2025 → несуществующий 2027). Теперь `scanYears()` сам определяет текущий год
и обрезает окно; фильмы будущих лет дают пустой план вместо ошибки.

### Галерея изображений IMDb
- Клик по постеру фильма → полноэкранный лайтбокс; ссылка «смотреть всю галерею».
- Модалка-сетка с регулируемой раскладкой (2×2…6×6), постраничное листание,
  подписи типов (постер / кадр / за кадром / промо), ленивые уменьшенные превью.
- Полноэкранный просмотр любого изображения со стрелками и клавиатурной навигацией.
- `GET /api/imdb/images` — прокси галереи с пагинацией;
  `GET /api/imdb/images/zip` — потоковый ZIP всех изображений (fflate, режим store,
  скользящее окно предзагрузки, учёт backpressure).

### Подбор фильма с Кинопоиска
- Кнопка-бинокль в форме «Найти все награды фильма»: модалка с результатами поиска
  Кинопоиска (постер, название, год, режиссёр, рейтинг, жанры), сортировка от новых
  к старым, выбор подставляет название и год.
- `GET /api/search/kp-suggest` + парсер `src/lib/kp-suggest.ts` — прямого API подсказок
  у Кинопоиска больше нет, поэтому парсится живая страница поиска через Jina Reader.

### Исправления надёжности и безопасности (ноябрь 2026)

**Ошибки**
- Скачивание ZIP: после отмены загрузки сервер оставался в вечном цикле ожидания.
  Теперь отмена останавливает и цикл, и загрузку картинок; архив начинает отдаваться
  после первой страницы галереи, одновременно собирается не больше двух архивов.
- Временный сбой источника больше не записывается как «страницы нет» на сутки.
- Поиск фильма не выдаёт чужие номинации из-за совпадения части слова.
- Неполные данные IMDb (API ограничил запросы посреди загрузки) помечаются, показываются
  с предупреждением и кнопкой «Дозагрузить» и не подменяют полные в кэше.
- Ошибки 4xx от IMDb не повторяются по шесть раз (несуществующий ID отвечает сразу).
- Кэш отчётов и церемоний текущего года обновляется (раньше оставался без победителей).

**Безопасность**
- Сохранение/удаление ключа TMDB требует `ADMIN_TOKEN` (раньше — любой посетитель).
- Лимит запросов с одного адреса на сканирование, построение отчётов, поиск и ZIP;
  одинаковые одновременные запросы к источникам объединяются.
- Контейнер работает не от root, пароль БД вынесен в `.env`.

**Инфраструктура**
- Миграции вместо `drizzle-kit push` при каждом старте; образ собирается как
  `standalone` без dev-зависимостей; healthcheck контейнера.
- Тесты, CI (lint, typecheck, test, build), структурированные логи сбоев источников.

## API (основное)

| Endpoint | Назначение |
|---|---|
| `POST /api/report` `{url, refresh?}` | Построить/обновить отчёт по ссылке на премию |
| `GET /api/search/plan?year=2025` | План сканирования для года фильма |
| `POST /api/search/scan` | Сканировать одну пару «премия+год» → `ok` / `missing` / `error` |
| `GET /api/search/results?q=…&year=…[&kp=…]` | Поиск фильма по кэшу отчётов (`kp` — id фильма на Кинопоиске) |
| `GET /api/search/kp-suggest?q=…` | Подбор фильма на Кинопоиске |
| `GET /api/imdb/search?q=…` | Поиск титула на IMDb |
| `GET /api/imdb/awards?id=tt…` | Все номинации титула |
| `GET /api/imdb/images?id=tt…` | Галерея изображений (страницы) |
| `GET /api/imdb/images/zip?id=tt…` | Вся галерея одним ZIP |
| `GET /api/export/{xlsx,md,html}` | Экспорт отчётов |
| `POST/DELETE /api/tmdb/key` | Ключ TMDB; заголовок `x-admin-token` обязателен |
| `GET /api/health` | Health-check для мониторинга |

# 🐳 Развёртывание «Кинонаграды» в Docker

Полная инструкция по запуску сервиса отчётов о кинонаградах (Кинопоиск + IMDb + TMDB)
на любой машине с Docker.

## Состав

| Файл | Назначение |
|---|---|
| `Dockerfile` | Многослойная сборка образа приложения (Node 22 Alpine) |
| `docker-compose.yml` | Оркестрация: PostgreSQL 16 + приложение |
| `drizzle/` | SQL-миграции схемы БД — применяются автоматически при старте приложения |
| `.env.example` | Шаблон файла `.env` с паролем БД, токеном администратора и ключами |
| `.dockerignore` | Исключения из контекста сборки |

## Требования

- Docker Engine 24+ и Docker Compose v2 (`docker compose version`)
- ~2 ГБ свободного места (образ + база)
- Доступ в интернет из контейнера (сервис обращается к kinopoisk.ru через
  Jina Reader, api.imdbapi.dev, themoviedb.org)

## Быстрый старт

```bash
# 1. Клонируйте / скопируйте проект и перейдите в его корень
cd <папка-проекта>

# 2. Соберите и запустите
docker compose up -d --build

# 3. Откройте в браузере
#    http://localhost:3000
```

При первом запуске:
1. Поднимается PostgreSQL с постоянным томом `pgdata`
2. Приложение дожидается готовности БД (healthcheck + собственное ожидание до 60 с)
3. Применяются миграции из `drizzle/` — создаются все таблицы. Применённые миграции
   запоминаются, при следующих стартах выполняются только новые
4. Стартует production-сборка Next.js на порту 3000 (под непривилегированным
   пользователем `node`); состояние контейнера видно в `docker compose ps` (healthcheck
   опрашивает `/api/health`)

> **Обновление со старой версии** (где схему создавал `drizzle-kit push`): ничего делать
> не нужно. Базовая миграция идемпотентна (`CREATE … IF NOT EXISTS`) — на существующей
> базе она ничего не меняет, данные и кэш сохраняются.

## Переменные окружения

Задаются в файле `.env` рядом с `docker-compose.yml` (шаблон — `.env.example`):

```bash
cp .env.example .env    # и впишите нужные значения
docker compose up -d
```

| Переменная | Обязательна | Описание |
|---|---|---|
| `POSTGRES_PASSWORD` | нет (по умолчанию `postgres`) | Пароль БД. Действует только при первом создании тома `pgdata`; из него же собирается `DATABASE_URL` приложения |
| `ADMIN_TOKEN` | нет | Токен администратора. Без него ключ TMDB через интерфейс нельзя ни сохранить, ни удалить (ключ общий для всех посетителей) |
| `TMDB_API_KEY` | нет | v3-ключ TMDB — включает поиск на странице `/tmdb`. Получить: themoviedb.org → Settings → API |
| `TMDB_ACCESS_TOKEN` | нет | Альтернатива: v4 Read Access Token TMDB (достаточно одного из двух) |
| `JINA_API_KEY` | нет | Ключ r.jina.ai — повышает лимиты загрузки страниц Кинопоиска |

Внутри контейнера приложение дополнительно понимает `DATABASE_URL` (собирается в compose),
`PORT` (по умолчанию 3000) и `SKIP_DB_MIGRATIONS=1` (не применять миграции при старте).

Сменить пароль у уже существующей базы:

```bash
docker compose exec db psql -U postgres -c "ALTER USER postgres PASSWORD 'новыйпароль'"
# затем впишите его в .env (POSTGRES_PASSWORD) и перезапустите: docker compose up -d
```

## Полезные команды

```bash
docker compose up -d --build      # сборка + запуск в фоне
docker compose logs -f app        # логи приложения
docker compose logs -f db         # логи PostgreSQL
docker compose ps                 # статус контейнеров
docker compose restart app        # перезапуск приложения
docker compose down               # остановка (данные БД сохраняются)
docker compose down -v            # остановка + УДАЛЕНИЕ данных БД
```

### Доступ к базе данных

```bash
# psql внутри контейнера
docker compose exec db psql -U postgres -d app_db

# Примеры запросов
#   \dt                                 -- список таблиц
#   select award_slug, year from reports;
#   select imdb_id from imdb_titles;
```

Чтобы подключаться с хоста (DBeaver, pgAdmin), раскомментируйте `ports: - "5432:5432"`
у сервиса `db` и перезапустите compose.

## Обновление приложения

```bash
git pull                          # или скопируйте новую версию кода
docker compose up -d --build      # пересборка изменённых слоёв
```

Слой `npm ci` кэшируется — пересборка без изменения зависимостей занимает ~1 минуту.
Новые миграции БД применяются сами при старте контейнера.

### Изменение схемы БД (для разработки)

```bash
# 1. поправьте src/db/schema.ts
npm run db:generate               # создаст новый SQL-файл в drizzle/
# 2. закоммитьте его — при следующем старте приложения он применится
```

## Резервное копирование БД

```bash
# Дамп
docker compose exec db pg_dump -U postgres app_db > backup.sql

# Восстановление
cat backup.sql | docker compose exec -T db psql -U postgres -d app_db
```

## Архитектура образа

```
┌─────────────── этап deps ───────────────┐
│ npm ci → полный node_modules            │
└──────────────────┬──────────────────────┘
                   ▼
┌────────────── этап builder ─────────────┐
│ next build → .next/standalone           │
└──────────────────┬──────────────────────┘
                   ▼
┌────────────── этап runner ──────────────┐
│ standalone-сервер (server.js + только   │
│ нужные модули) + статика + public +     │
│ drizzle (миграции); USER node           │
│ CMD: node server.js                     │
└─────────────────────────────────────────┘
```

В финальном образе нет ни dev-зависимостей, ни исходников — только то, что нужно
для работы сервера.

## Устранение неполадок

| Симптом | Решение |
|---|---|
| Контейнер `app` перезапускается, в логах `"migration failed"` | БД недоступна или миграция не применилась: смотрите текст ошибки в `docker compose logs app` и `docker compose logs db`; проверьте, что пароль в `.env` совпадает с паролем существующей базы |
| Порт 3000 занят | Измените проброс в compose: `"8080:3000"` → http://localhost:8080 |
| Отчёты Кинопоиска не строятся | Из контейнера должен быть доступен `r.jina.ai`; проверьте: `docker compose exec app wget -qO- https://r.jina.ai` |
| `/tmdb` просит ключ | Добавьте `TMDB_API_KEY` в `.env` и `docker compose up -d` — либо задайте `ADMIN_TOKEN` и введите ключ в интерфейсе |
| Ответ `429 Слишком много запросов` | Сработал лимит запросов с одного адреса (окно 10 минут). За reverse-proxy убедитесь, что он передаёт `X-Forwarded-For`, иначе все посетители считаются одним клиентом |
| Что именно не загрузилось | Все сбои внешних источников пишутся в лог одной JSON-строкой: `docker compose logs app \| grep '"level":"warn"'` |
| Медленная первая сборка | Нормально: `npm ci` ставит ~500 пакетов. Дальше работает кэш |
